1# 单机多节点部署方案（方案 A：无状态水平扩容）
2
3> 场景：**一台机器**上运行多个 OneTrans 节点，用**端口**区分，内部统一回环地址 `127.0.0.1`。
4> 目标：`/rank` 由 3 个打分节点分担，`/ingest` 由 2 个专职灌缓存节点处理，共享 PS 与 DataSystem，外接 Nginx 统一入口。
5> 本文为**单一自洽完整版**，可直接从零执行到验收。
6

8
9## 0. 端口分配（整个文档统一使用）
10
11| 进程 | 端口 | 说明 |
12|---|---|---|
13| PS（embedding 表） | 18000 | brpc |
14| DataSystem worker（S 缓存 KV） | 31501 | 需共享内存 ≥6GiB |
15| ingest pod ×2 | 8191 / 8192 | 专职灌 S 缓存 |
16| rank/score pod ×3 | 8181 / 8182 / 8183 | 在线精排 |
17| Nginx（LB） | 8080 | 唯一对外入口 |
18| PaiRec | 18080 | sort/recall 框架 |
19
20所有地址统一填 `127.0.0.1`。

59## 3. 准备数据物料
60
61### 3.1 Python 环境
62```bash
63CC=gcc CXX=g++ uv sync        # 按 uv.lock 建 .venv（requires-python>=3.14，含 torch）

66### 3.2 按路线准备（A=v42 音乐域已有权重；B=tenrec 需重建）
67
68**路线 B（tenrec 视频域）物料：**
69```bash
70mkdir -p artifacts/domain_features artifacts/itemset
71
72# B1 特征表（awk 扫 ctr_data_1M.csv 生成两份）
73awk -v ITEM_FEATURES=artifacts/domain_features/item_features.tsv \
74    -v USER_FEATURES=artifacts/domain_features/user_features.tsv \
75    -f onetrans/tools/build_domain_features.awk Tenrec_data/ctr_data_1M.csv
76
77# B2 item 词表 + embedding
78cut -d, -f2 Tenrec_data/ctr_data_1M.csv | tail -n +2 | sort -u > /tmp/distinct_items.txt
79.venv/bin/python -m onetrans.tools.build_item_embedding \
80    --input /tmp/distinct_items.txt --out-dir artifacts/itemset --d-model 128 --seed 42
81
82# B3 三张 PS 灌表二进制
83.venv/bin/python -m onetrans.tools.export_item_ps \
84    --item-dir artifacts/itemset --out artifacts/itemset/item_ps.bin
85.venv/bin/python -m onetrans.tools.gen_ps_table \
86    --ids-file artifacts/domain_features/user_features.tsv \
87    --out artifacts/itemset/user_ps.bin --dim 128 --seed 42
88.venv/bin/python -m onetrans.tools.gen_ps_table \
89    --ids 0,1,2 --out artifacts/itemset/artist_ps.bin --dim 128 --seed 43
90
91# B4 精排增量：album 表 + item_rank_lookup.tsv（dense 反查表，供 /rank 自装配）
92.venv/bin/python -m onetrans.tools.gen_ps_table \
93    --ids 0,1 --out artifacts/itemset/album_ps.bin --dim 128 --seed 45
94awk -F'\t' 'BEGIN{print "item_id\tartist_ids\talbum_ids\td1\td2\td3\td4\td5\td6\td7\td8\td9\td10\td11\td12\td13\td14\td15"}
95NR>1{
96  printf "%s\t%s\t%s",$1,$2,$2;
97  printf "\t%s\t%s\t%s\t%s\t%s\t%s",$2,$3,$11,$8,$9,$10;
98  printf "\t%s\t%s\t%s\t%s\t%s\t%s",$12,$13,$14,$17,$15,$16;
99  printf "\t%s\t%s\t%s\n",$4,$5,$6;
100}' artifacts/domain_features/item_features.tsv > artifacts/domain_features/item_rank_lookup.tsv
101# 自检：awk -F'\t' '{print NF}' artifacts/domain_features/item_rank_lookup.tsv | sort -u   # 期望 18
102```
103
104**路线 A（v42）**：权重已在 `cpp/artifacts/weights/`，跳过 B1–B4。

108## 4. 起共享服务（必须先于所有节点；本机各一份）
109
110```bash
111# ① PS（纯内存，重启即失，须随后重灌表）
112/var/tmp/ps-build/out/embedding_server --port=18000 --num_shards=64 --dim=128 &
113sleep 1 && curl -s 127.0.0.1:18000/healthz
114
115# ② DataSystem worker（按 DataSystem 0.8.1 部署方式启动，监听 127.0.0.1:31501）
116sudo mount -o remount,size=8G /dev/shm        # 共享内存扩到 8GiB
117export LD_LIBRARY_PATH="$DS_SDK/lib:$LD_LIBRARY_PATH"
118# 用 与 OneTrans client SDK 版本(0.8.1)匹配的 worker 启动，host/port=127.0.0.1:31501
119# 验证：http://127.0.0.1:31501/healthz 应返回 kv_objects 字段（错误则提示 worker 未就绪）
120```
121> ⚠️ 若 DataSystem worker 与 OneTrans 内置 0.8.0 SDK 协议不匹配，会收 `fd=0`、`/healthz` 恒 0。务必同版本。

147## 6. 起 ingest 池（2 台，专职灌 S 缓存）
148
149```bash
150cd /home/yb/gitcode/OneTrans_HSE_project
151# 第 1 台
152nohup ./cpp/build/onetrans_server \
153  --weights cpp/artifacts/weights --host 0.0.0.0 --port 8191 \
154  --lookup-threads 4 --encode-threads 2 --kv-threads 4 --compute-threads 4 \
155  --nearline-threads 16 --queue-cap 2048 --max-batch 32 --max-wait-ms 3 \
156  --embedding-source ps --ps-server 127.0.0.1:18000 \
157  --kv-backend datasystem --datasystem-host 127.0.0.1 --datasystem-port 31501 \
158  --kv-ttl-seconds 86400 \
159  --model-version v42 --model-role engineering \
160  --rank-item-lookup artifacts/domain_features/item_rank_lookup.tsv \
161  --rank-user-features artifacts/domain_features/user_features.tsv \
162  --compute-backend cpp > /tmp/ingest1.log 2>&1 &
163# 第 2 台（仅 --port 8192）
164nohup ./cpp/build/onetrans_server --weights cpp/artifacts/weights --host 0.0.0.0 --port 8192 \
165  --lookup-threads 4 --encode-threads 2 --kv-threads 4 --compute-threads 4 \
166  --nearline-threads 16 --queue-cap 2048 --max-batch 32 --max-wait-ms 3 \
167  --embedding-source ps --ps-server 127.0.0.1:18000 \
168  --kv-backend datasystem --datasystem-host 127.0.0.1 --datasystem-port 31501 \
169  --kv-ttl-seconds 86400 --model-version v42 --model-role engineering \
170  --rank-item-lookup artifacts/domain_features/item_rank_lookup.tsv \
171  --rank-user-features artifacts/domain_features/user_features.tsv \
172  --compute-backend cpp > /tmp/ingest2.log 2>&1 &
173```
174> 路线 B：把 `--model-version v42` 换成 `--model-version tenrec`（与 PS 表前缀一致）。

185## 7. 起 rank/score 池（3 台，在线精排）
186
187```bash
188cd /home/yb/gitcode/OneTrans_HSE_project
189for port in 8181 8182 8183; do
190nohup ./cpp/build/onetrans_server \
191  --weights cpp/artifacts/weights --host 0.0.0.0 --port $port \
192  --lookup-threads 8 --encode-threads 4 --kv-threads 8 --compute-threads 16 \
193  --nearline-threads 0 --queue-cap 2048 --max-batch 64 --max-wait-ms 5 \
194  --embedding-source ps --ps-server 127.0.0.1:18000 \
195  --kv-backend datasystem --datasystem-host 127.0.0.1 --datasystem-port 31501 \
196  --kv-ttl-seconds 86400 --model-version v42 --model-role engineering \
197  --rank-item-lookup artifacts/domain_features/item_rank_lookup.tsv \
198  --rank-user-features artifacts/domain_features/user_features.tsv \
199  --compute-backend cpp > /tmp/rank$port.log 2>&1 &
200done
201```
202> 单机建议 `--compute-backend cpp` 且 `--compute-threads 16`（不堆满），避免 3 个节点抢同一机器 CPU/GPU 造成抖动。路线 B 同样把 `--model-version` 换 `tenrec`。
203
204验证：`for p in 8181 8182 8183; do curl -s 127.0.0.1:$p/healthz; done`

208## 8. 起 Nginx（单一入口 8080）
209
210**做法：新建一个独立的 nginx 配置**，例如 `deploy/nginx-onetrans.conf`：
211
212```nginx
213worker_processes 1;
214error_log /tmp/nginx-onetrans-error.log;
215pid       /tmp/nginx-onetrans.pid;
216events { worker_connections 1024; }
217http {
218    upstream onetrans_online  { least_conn; server 127.0.0.1:8181; server 127.0.0.1:8182; server 127.0.0.1:8183; }
219    upstream onetrans_ingest  { server 127.0.0.1:8191; server 127.0.0.1:8192; }
220    server {
221        listen 8080;
222        location /rank    { proxy_pass http://onetrans_online;  proxy_read_timeout 3s; }
223        location /score   { proxy_pass http://onetrans_online;  proxy_read_timeout 3s; }
224        location /ingest  { proxy_pass http://onetrans_ingest;  proxy_read_timeout 10s; }
225        location /healthz { proxy_pass http://onetrans_online;  proxy_next_upstream off; }
226        location /metrics { proxy_pass http://onetrans_online;  proxy_next_upstream off; }
227    }
228}
229```
230```bash
231nginx -t -c /home/yb/gitcode/OneTrans_HSE_project/deploy/nginx-onetrans.conf   # 校验
232nginx     -c /home/yb/gitcode/OneTrans_HSE_project/deploy/nginx-onetrans.conf   # 启动
233curl -s http://127.0.0.1:8080/healthz    # 应返回某 rank 节点的 JSON
234```
235> 之后 **PaiRec 只连 8080**；加/减节点只改 nginx `upstream`，不动 PaiRec。

282## 11. 起停脚本（可选）
283
284**start_all.sh**（按序：大体两类服务 → 再灌表 → 再节点 → LB → PaiRec）
285```bash
286#!/usr/bin/env bash
287set -e
288cd "$(dirname "$0")/.."
289# 1 共享服务
290/var/tmp/ps-build/out/embedding_server --port=18000 --num_shards=64 --dim=128 &
291export LD_LIBRARY_PATH="$DS_SDK/lib:$LD_LIBRARY_PATH"
292<启动 datasystem worker 127.0.0.1:31501>  &
293sleep 3
294# 2 灌表（用脚本内已灌的 bin，或任选一并重复）
295(cd cpp && ./build/ps_load --source weights --weights ../cpp/artifacts/weights --prefix v42 --server 127.0.0.1:18000)
296# 3 节点
297for port in 8191 8192; do <第6步 ingest 启动命令精简> ; done
298for port in 8181 8182 8183; do <第7步 rank 启动命令精简> ; done
299# 4 LB
300nginx -t -c "$PWD/deploy/nginx-onetrans.conf" && nginx -c "$PWD/deploy/nginx-onetrans.conf"
301# 5 PaiRec
302CONFIG_PATH=configs/pairec_config.onetrans_rank.json nohup ./bin/pairec > /tmp/pairec.log 2>&1 &
303```
304
305**stop_all.sh**（逆序回收）
306```bash
307#!/usr/bin/env bash
308nginx -s stop || true
309pkill -f onetrans_server   || true
310pkill -f datasystem.worker || true
311pkill -f embedding_server  || true
312pkill -f 'bin/pairec'      || true
313```
314> ⚠️ 重启后 PS 表会清空（无持久化），必须重跑 `ps_load`（start_all 已含）。

318## 12. 常见坑速查
319
320| 现象 | 原因 | 处理 |
321|---|---|---|
322| 某节点启动即退出 | PS 未起或不可用（`PsLookupClient.available()` false） | 先起 PS 再起节点 |
323| `/healthz` kv_objects 恒 0 | DataSystem worker 未就绪 / 版本不匹配 / shm 不足 | 扩 shm 到 8G、对齐 0.8.1、确认 worker 注册成功 |
324| 缺 `album` 表 | 灌表漏 `--table album` | 补灌 `album_ps.bin` |
325| `/rank` item_id 全是 0 | 老版本 `as_int()` bug | 用已修复版本（string 类型 `item_id` 解析） |
326| PaiRec 返回空结果/契约失败 | `--model-role` 与 `required_model_role` 不一致 | 两处统一 `engineering` |
327| 多节点 S 缓存互不可见 | 节点用了 `--kv-backend local` | 全部改 `--kv-backend datasystem` 指向同一 worker |
